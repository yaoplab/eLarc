## 1. Bugs fonctionnels — preuves base live

> Base vérifiée : NewLarcDB (127.0.0.1:55515, PG 15.18) — 2400 élèves (1994 slots libres), 60 classes, 37 `student_event`, 12 termes, 4655 utilisateurs.

### 1.1 P1 — Terme actif : app verrouillée sur l'année scolaire 2025-2026
- **Code** : `main_window.py:734`, `login.py:99`, `login.py:374`, `data_loader.py:59` — `WHERE ay.s_id = 1 AND t.trim = ay.current_term_number`
- **Données live** : `larcauth_academicyear` contient 2 lignes : `s_id=1` (« 2025-2026 », `current_term_number=3`) et **`s_id=2` (« 2026-2027 », `current_term_number=1`, créée le 2026-08-09)**.
- **Conséquence** : l'app charge le terme 3 de l'an dernier (« 3e Trimestre », terminé le 19 juin) au lieu du T1 2026-2027. Le libellé affiché (top bar, login) est celui de l'an passé.
- **Correctif proposé** : remplacer `ay.s_id = 1` par la ligne la plus récente (`ORDER BY ay.s_id DESC LIMIT 1` ou `WHERE ay.start_date <= CURRENT_DATE AND ay.end_date >= CURRENT_DATE`) + `ORDER BY t.id` + filtre langue (`fk_language`).

### 1.2 P1 — `get_term_id()` renvoie le numéro de trim, pas l'id de terme
- **Code** : `data_loader.py:38-51` — retourne `ay.current_term_number` (valeur live : **3**), mais est utilisé comme `term_id` dans `event_generator.py:329` pour filtrer `cts.fk_term_id = %s` — or les ids de `larcauth_term` sont 1..12.
- **Conséquence** : le wizard charge les matières du « 2nd Term » (id 3, trim 2) au lieu du terme voulu ; le fallback silencieux (`data_loader.py:686-699`) affiche alors les matières de **tous** les termes.
- **Correctif** : résoudre trim → id comme `main_window.py:731-736`, ou renommer `get_term_id()` en `get_term_number()`.

### 1.3 P1 — Préférences jamais persistées (table inexistante)
- **Code** : `main_window.py:796, 1527-1533` ; `preferences.py:146-157` — `SELECT/INSERT INTO larcauth_config` sous `try/except` silencieux.
- **Vérifié live** : `ERREUR: la relation "larcauth_config" n'existe pas`. Le DDL n'existe que dans `LarcSecretaire\docs\app_config.sql`, jamais appliqué.
- **Conséquence** : thème, langue, taille de vignettes — ni chargés ni sauvegardés, sans aucun message.
- **Correctif** : appliquer le DDL `larcauth_config` (et le déplacer dans `LarcSuperviseur/sql/`), logger l'échec au lieu de l'avaler.

### 1.4 P2 — Garde-fou des dates futures mort (`FROM agenda`)
- **Code** : `event_generator.py:538` — `SELECT MAX(date_all) FROM agenda` ; la table live s'appelle `larcauth_agenda`. Exception avalée ligne 549 → le blocage des dates futures ne s'exécute **jamais**.

### 1.5 P2 — INSERT `student_event` sans `agenda_day_id` (dépendance trigger)
- **Code** : `data_loader.py:535-558`, `main_window.py:1554-1567` — INSERT sans `agenda_day_id` (`NOT NULL` en base).
- **Conséquence** : le trigger `resolve_agenda_day` lève `RAISE EXCEPTION 'Aucun jour agenda trouvé...'` pour les week-ends/congés/dates non générées → l'événement n'est jamais enregistré. Et sans trigger (voir 3.1), 100 % des inserts échouent.

### 1.6 P2 — Résolution trim→id ambiguë (`LIMIT 1` sans tri ni langue)
- **Code** : `main_window.py:731-736`, `login.py:96-100`, `data_loader.py:56-60`.
- **Vérifié live** : le trim 1 correspond à 4 termes (ids 1, 2, 7, 10 — FR/EN × 2 années). L'id et le libellé retenus sont arbitraires.
- **Correctif** : filtre `fk_language` + `ORDER BY t.id DESC`.

### 1.7 P2 — `class_panel.py:94` : `_` i18n utilisé comme entier (code latent)
- **Code** : `addWidget(sp, len(cards) // cols, cols - remaining + _, ...)` alors que `_` est la fonction i18n (importée ligne 2). La boucle ligne 90 utilise `_unused`.
- **Atténuation** : `ClassPanel` n'est **instancié par aucune vue** (main_window construit sa propre grille) → NameError/TypeError latente uniquement.
- **Correctif immédiat** : `cols - remaining + _unused` (1 caractère).

### 1.8 P1 — SQLi pattern (f-string de sigle) + `IN (...)` concaténé
- **Code** : `data_loader.py:178-179` — `f"AND p.sigle ILIKE '{sigle}'"` (sigle transite depuis l'UI, `grp_{sigle}`) ; doublons `main_window.py:876-877` et `1212-1214`. Aussi `data_loader.py:384` et `main_window.py:1375-1376` : `IN ({ids_sql})` par concaténation.
- **Correctif** : whitelist `{mode → filtre}` ou paramètre `%s` ; `%s` + `mogrify`/`unnest(%s::int[])`.

### 1.9 P1 — Crash : `self._actions` jamais initialisé (menu contextuel historique global)
- **Code** : `main_window.py:1704` — `event = self._actions.get_event_by_id(eid)` : **seule occurrence** de `self._actions` dans le fichier, jamais assignée (seul `student_detail.py` fait `self._actions = EventActions()`).
- **Scénario** : clic droit sur une ligne de la table historique → AttributeError non catchée (slot sans `@safe_slot` ni try/except) → menu jamais ouvert.
- **Correctif** : `self._actions = EventActions()` dans `MainWindow.__init__`.

### 1.10 P1 — Wizard inutilisable : `larcauth_type_status` absente de la base
- **Code** : `event_generator.py:124-141` — `SELECT ... FROM larcauth_type_status WHERE fk_language = %s AND "Enabled" = TRUE` (2 requêtes : modes + absences/retards).
- **Vérifié live** : la table n'existe pas dans NewLarcDB (84 tables listées ; seule `larcauth_type_event` existe, 57 lignes). L'exception est avalée (l.151-152) → `self._modes` vide → **écran de choix de mode vide, wizard inutilisable** (le mode « Autres » reste le seul chemin possible, alimenté par `get_event_types_tree()`).
- **Correctif** : alimenter `_modes` depuis `larcauth_type_event` (hiérarchie existante) ou créer la table ; afficher un message d'erreur si la liste est vide.

### 1.11 P1 — Éditeur emploi du temps cassé : `classroom_has_timeperiod` sans préfixe
- **Code** : `data_loader.py:794, 813, 840, 845` — `FROM classroom_has_timeperiod` / `UPDATE classroom_has_timeperiod` alors que la table s'appelle `larcauth_classroom_has_timeperiod` (utilisée correctement l.752).
- **Scénario** : `TimetableEditor` (`get_classroom_timetable`, `get_available_subjects`, `update_timetable_slot`) → UndefinedTable avalée → **grille EDT toujours vide, modifications silencieusement impossibles**.
- **Correctif** : préfixer `larcauth_` sur les 4 requêtes.

### 1.12 P1 — Compteurs d'absences incohérents (3 jeux de motifs)
- **Code** : le wizard stocke `event_type = "Absence > <nature>"` (event_generator.py:481). `data_loader.py:443-458` compte `= 'absence'` ou `ILIKE 'Suivi > Absence%'` ; `main_window.py:898-906` utilise 3 motifs dont `Absence%`. Mêmes motifs incomplets dans `get_student_event_stats`, `get_attendance_trend`, `get_presence_rate`, `get_class_stats`, `get_student_absence_trend` (`data_loader.py:389, 236, 272, 202, 479`). Aussi `%Fuite%` vs libellé réel « Fugue » (`data_loader.py:190, 202, 397, 444`).
- **Scénario** : absence créée via le wizard → visible dans la table et le donut du détail élève, mais **KPI absences = 0** et la carte de classe affiche « Présent » ; une fugue n'apparaît dans aucun compteur de sorties.
- **Correctif** : uniformiser les motifs (`ILIKE 'Absence%'` partout) ou stocker un `event_type` canonique.

### 1.13 P2 — Bugs de cas limites du wizard (revue fonctionnelle)
- **Crumb lieu** : `event_generator.py:424-430` — clic sur le crumb lieu → `lieu_id` conservé mais `lieu_label` vidé → événement enregistré **sans lieu**.
- **Retard + élève sans classe** : `_show_subjects`/`_show_type_options` → grille vide bloquante (étape finale exige `len(path) >= 3`).
- **Double étape catégorie** : lieu-classe + élève sans `s_classroom_id` → liste des catégories affichée deux fois → `event_type` dupliqué/mixé (« Bureau BI > Bureau BI »).
- **KPI « présents »** : `main_window.py:920` compte des **événements** (pas des élèves distincts) et inclut les absences validées → incohérent avec la liste des absents.
- **Tri de dates** : `student_detail.py:403` — tri lexicographique de `"%d/%m"` → ordre faux à cheval sur deux mois.
- **`QTableWidgetItem(None)`** : `student_detail.py:338`, `main_window.py:1285` — `creator` NULL (LEFT JOIN) → TypeError en PySide6, page non protégée.
- **LIMIT 20** : `student_detail.py:310` — table/donut/barres sur 20 événements, KPIs sur toute la période.
- **`get_locations`** : `data_loader.py:654` — `fk_language = 2` codé en dur → lieux FR pour un utilisateur EN.

### 1.14 P3 — Autres (détail dans rapport infra)
- `toggle_validation` tripliqué (`data_loader.py:599-618`, `event_actions.py:76-96`, `main_window.py:1737-1758`) — SELECT-then-UPDATE non atomique sous autocommit (TOCTOU).
- `event_dialog.py:20` — connexion snapshotée à l'ouverture du dialogue (pas de re-fetch).
- Curseurs jamais fermés dans `data_loader.py` (~30 méthodes) — GC suffisant en pratique.
- `get_active_term()` (`data_loader.py:24-36`) : résolution par dates, contraire à la convention `current_term_number`, n'est utilisé par **aucune vue** (tests seulement) → retourne 0 pendant les vacances scolaires.
- `EventActions.get_context_menu` (event_actions.py:112-133) : code mort, divergent des menus réels (student_detail/main_window).
